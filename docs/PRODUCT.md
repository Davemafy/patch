# Patch product contract

## One sentence

**Something broke at home? Tell Patch. We'll get you real prices and times from people who can fix it.**

## User

An everyday person with a small home repair: broken doorknob, leaking tap, faulty socket, AC problem, stuck door, broken cabinet hinge, toilet issue, or similar job.

## Problem

The annoying part is not knowing that something broke. It is asking around:

- Who actually handles this?
- Who can come?
- When?
- What will it cost?
- Do I really need to call several people myself?

## Frozen journey

1. The user describes what broke and may add a photo.
2. Patch finds a small number of plausible people whose public websites say they handle that kind of repair.
3. The user asks them for price and time.
4. They receive an ordinary message. They do not need a Patch account.
5. Their real replies come back into Patch.
6. Patch shows the actual time and price from each reply.
7. The user chooses someone.

## The demo moment

User reports: “My bedroom doorknob is broken. The handle turns but the door won't open properly.”

A repair person replies: “I can come today at 2. It'll be ₦12,000.”

Patch updates to: **Tunde can come today at 2 PM for ₦12,000.**

The user never called anybody.

## Truth rules

- A website can prove service fit, not current availability.
- Only an actual reply can establish availability, price, or acceptance.
- Preserve the original reply behind any extracted facts.
- If a reply is unclear, show that it is unclear. Do not guess.
- The user chooses the repair person. Patch does not silently book or spend money.

## Not in scope

Payments, maps, contractor accounts, landlord tooling, marketplace profiles, reviews, subscriptions, analytics dashboards, in-app chat, automatic booking, or an “AI assistant” screen.
